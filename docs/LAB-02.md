# Лабораторна 02 — зі звуку отримуємо ноту

Для докладного читання: [pitch.ts із коментарями до кожного рядка та поясненнями під блоками](PITCH-LINE-BY-LINE.md).

**Мета:** зіграти один звук і побачити його виміряну частоту, ноту та відхилення від правильного налаштування. Код підключений до мікрофона й тестового генератора на обох сторінках.

> **Частота** — кількість коливань за секунду; вимірюється в Hz (герцах). **Нота** — музична назва висоти звуку, наприклад Ля.

## 1. Спочатку перевіряємо результат

Запусти `npm run dev`, відкрий адресу з термінала й натисни **«Тестовий сигнал»**. Значення біля повзунка ми задаємо самі. Число біля ноти обчислюється зі звуку незалежно від повзунка.

> **Тестовий генератор** — код, що створює сигнал із відомою частотою. Так можемо перевірити відповідь програми.

За еталона A4 = 440 Hz очікуємо:

| Задай повзунком | Очікуваний результат           |
| --------------- | ------------------------------ |
| 440 Hz          | A4 / Ля, приблизно 0 центів    |
| 220 Hz          | A3 / Ля на октаву нижче        |
| 880 Hz          | A5 / Ля на октаву вище         |
| 430 Hz          | A4, відхилення зі знаком мінус |
| 450 Hz          | A4, відхилення зі знаком плюс  |
| Амплітуда 0     | Після затихання нота зникає    |

> **Еталон A4** — обрана правильна частота ноти Ля четвертої октави. **Октава** — перехід до вдвічі більшої або меншої частоти; назва ноти повторюється.
>
> **Цент** — одна сота півтону. Невеликий мінус означає «нижче потрібної ноти», плюс — «вище». **Амплітуда** — розмір коливань; нуль означає відсутність сигналу.

Потім зупини тест, увімкни мікрофон і протягни «ааа» або зіграй одну струну. Порівняй назву ноти, частоту та стрілку. Зіграй лише одну ноту, без акорду.

> **Акорд** — поєднання кількох нот. Ця версія шукає один тон, тому для акорду відповідь може бути хибною.

## 2. Перший файл для розбору — `src/audio/pitch.ts`

Цей файл отримує масив семплів. Він перевіряє, чи сигнал достатньо сильний, і передає його в Pitchy. Бібліотека повертає частоту та clarity.

> **Семпл** — одне число: значення сигналу в один момент часу. **Pitchy** — бібліотека для визначення основної частоти одного тону. **Clarity** — число від 0 до 1, що описує вираженість тону за оцінкою бібліотеки; це не відсоток гарантії правильної ноти.

Головний рядок:

```ts
const [frequency, clarity] = this.detector.findPitch(this.centered, sampleRate);
```

> **frequency** — обчислена частота. **sampleRate** — кількість семплів за секунду, отримана з AudioContext. Детектору вона потрібна, щоб перевести відстань між повтореннями у Hz.

`centered` — копія сигналу, з якої відняли середнє значення. Наприклад, рівна лінія зі значенням 0.5 не має коливань і не повинна вважатися тоном.

> **Постійне зміщення / DC offset** — коли середній рівень хвилі зсунуто вище або нижче нуля. Віднімання середнього прибирає цей зсув.

У цьому файлі є початкові правила: мінімальний рівень −55 dBFS, мінімальна clarity 0.9, діапазон 60–1500 Hz. Їх обрано для першої реалізації; перевірка на різних пристроях ще попереду. Вони зменшують кількість випадкових відповідей, але не гарантують відкидання будь-якого шуму.

> **dBFS** — шкала цифрового рівня сигналу. **Поріг** — граничне значення, за яким вирішуємо, чи приймати результат.

Результат `detected` містить частоту. Для `quiet`, `unclear` і `out-of-range` повертаємо `frequency: null`, щоб стара нота не залишалася на екрані.

> **detected** — тон визначено; **quiet** — надто тихо; **unclear** — чіткого тону немає; **out-of-range** — частота поза обраними межами.

## 3. Другий файл — `src/audio/notes.ts`

Тут перетворюємо вже виміряну частоту на найближчу ноту й октаву. Вихідна точка — A4: номер 69 і частота, вибрана користувачем, спочатку 440 Hz.

> **MIDI-номер** — числове позначення ноти й октави. Різниця в 12 номерів означає одну октаву.

```ts
const midi = Math.round(69 + 12 * Math.log2(frequency / referenceA4));
```

> **Math.log2** — двійковий логарифм. Тут він допомагає перейти від співвідношення частот до відстані між нотами: подвоєння частоти дає +12 номерів.

Знаючи найближчу ноту, обчислюємо її правильну частоту `targetFrequency`. Потім порівнюємо її з реальною частотою:

```ts
const cents = 1200 * Math.log2(frequency / targetFrequency);
```

> **targetFrequency** — цільова частота знайденої ноти. **cents** — відхилення від неї в центах; в октаві 1200 центів.

У межах ±5 центів показуємо зелений стан. Це початковий допуск інтерфейсу, а не заява про гарантовану точність вимірювань. Зміна еталона на 442 Hz змінить ціль, але не виміряну частоту звуку.

> **Допуск** — відхилення, яке ми погодилися вважати достатньо малим для напису «налаштовано».

## 4. Третій файл — `src/hooks/usePitchDetection.ts`

Цей хук бере актуальні семпли та запускає визначення приблизно кожні 75 ms. Отриманий результат через `AudioWorkspace.tsx` потрапляє в `TunerDisplay.tsx` або `NoteDisplay.tsx`. При Stop чи призупиненні аудіо попередній результат одразу приховується.

> **ms** — мілісекунди: 1000 ms = 1 секунда. Інтервал 75 ms — як часто намагаємося оновлювати результат; це не виміряна повна затримка від мікрофона до екрана.

Файли для розбору в порядку: **pitch.ts → notes.ts → usePitchDetection.ts → AudioWorkspace.tsx → TunerDisplay.tsx / NoteDisplay.tsx**. Не потрібно читати всі одразу. Почнемо з того, як у `pitch.ts` масив чисел стає частотою.

## 5. Перевірки та межі

`npm test` запускає 25 тестів. Для нової частини справжня Pitchy аналізує чисельно створені синусоїди на частотах гітарних струн, 440, 880 і 1000 Hz при частотах дискретизації 44.1, 48 та 96 kHz. Похибка у цих перевірках має бути меншою за 2 центи. Є також перевірки шуму, тиші, зміщення, одного складеного сигналу та формул нот.

> **Синусоїда** — проста плавна хвиля з однією частотою. **Похибка** — різниця між відомою правильною відповіддю та результатом програми.

Ці тести пройдені; фізичний мікрофон і взаємодію в браузері ще потрібно перевірити вручну. Поточні показники не згладжені, тому можуть коливатися. Гітарний режим підсвічує збіг із нотою відкритої струни, але не встановлює, яку фізичну струну зіграно. Сторінка нот використовує еталон 440 Hz.

> **Згладжування** — зменшення дрібних стрибків показників між вимірюваннями. Його вплив на стабільність і швидкість реакції дослідимо наступним кроком.

Ручна перевірка: тестові 220/440/880 Hz; 430/450 Hz; A4 440→442; амплітуда до нуля; Stop і повторний запуск; перехід між сторінками; голос/одна струна; відмова в дозволі. Старий результат не повинен залишатися після зупинки або тихого фрагмента.

Джерело API бібліотеки: [офіційний README Pitchy](https://github.com/ianprime0509/pitchy). Вибір порогів і код перетворення нот належать цьому проєкту.

## Словничок

| Слово           | Просте пояснення                                                        |
| --------------- | ----------------------------------------------------------------------- |
| Частота, Hz     | Скільки коливань відбувається за секунду                                |
| Семпл           | Одне числове значення сигналу в один момент                             |
| sampleRate      | Скільки семплів отримуємо за секунду                                    |
| Основна частота | Частота головного повторення сигналу, з якої визначаємо ноту            |
| Pitchy          | Бібліотека, яка шукає основну частоту одного тону                       |
| Clarity         | Оцінка вираженості тону, від 0 до 1; не ймовірність правильності        |
| DC offset       | Постійний зсув середнього значення хвилі від нуля                       |
| RMS, dBFS       | Оцінка рівня фрагмента сигналу та її запис у цифровій шкалі             |
| Поріг           | Граничне значення для прийняття рішення                                 |
| MIDI-номер      | Числове позначення ноти разом з октавою                                 |
| Октава          | Подвоєння або зменшення частоти вдвічі                                  |
| Еталон A4       | Обрана правильна частота ноти Ля четвертої октави                       |
| Цент            | Одна сота півтону; 1200 центів становлять октаву                        |
| Півтон          | Крок між сусідніми нотами дванадцятиступеневого строю, наприклад A і A♯ |
| Допуск          | Відхилення, яке приймаємо як достатньо мале                             |
| Згладжування    | Зменшення дрібних стрибків показників                                   |
| Акорд           | Кілька нот разом; у цій версії не розпізнаємо                           |
