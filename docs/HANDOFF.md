# Передача контексту (6. 11. 2026)

Цей файл — короткий стан проєкту для нової сесії Claude.

## Хто і що
- **Sonora**: словацька бакалаврська робота. Це вебзастосунок (React + Vite + TypeScript) для ladenia gitary і розпізнавання тонів та акордів у браузері (Web Audio API). Завдання вимагає: ШІ для акордів (користувач хоче), бекенд (профілі, налаштування, статистика; **ще не зроблено**), аналіз точності, тести продуктивності на різних пристроях і браузерах, аналіз ризиків.
- Пояснювати **українською**, терміни **словацькою** (ladička, vzorka, rámec…). Просто, «як дитині», з візуалом. DFT/FFT зрозумілі на ~75%, «метелики» ні.
- Код: **читабельність важливіша за оптимізацію**. Код і інтерфейс англійською. Коментарі лише практичні (чому саме таке значення, де його підібрано, підводні камені браузера); навчальні пояснення — у `docs/`, не в коді (9. 11. прибрано: 939 → 421 рядків коментарів, маркери BEGIN/END BLOCK теж).
- Git-репозиторію немає (рекомендовано `git init`, ще не зроблено). Комітити лише на прохання користувача.

## Що вже є
- **Тюнер**: Pitchy (McLeod), `MIN_CLARITY = 0.8`, згладжування (`pitchSmoother.ts`), режим гітари з вибором струни (`guitarStrings.ts`, `TunerDisplay.tsx`).
- **Акорди (DSP)**: FFT → Hann → `noiseFloor.ts` → `chroma.ts` → 24 шаблони (`chordTemplates.ts`, `chordMatcher.ts`) → `classifyChroma` (`chords.ts`) → `ChordStabilizer` з гістерезисом → адаптивний `LevelGate` проти гулу. Завжди показується ймовірний акорд (best guess). Сторінка `/#/chords`.
- **Записи + стенд + ШІ** (останній крок):
  - `/#/record` (`RecordWorkspace.tsx`, `takeRecorder.ts`, `wav.ts`, `datasetLabels.ts`): записи 3 с, файли `Am__03.wav`.
  - `npm run eval` / `npm run eval:synthetic` (`scripts/evaluate.ts`): точність, матриця помилок, швидкість, звіт у `docs/results/`.
  - Двигуни з однаковим інтерфейсом: `src/audio/engines/` (`dspEngine`, `basicPitchEngine`, `basicPitchBrowser`). Модель Basic Pitch лежить у `public/models/basic-pitch/`.
  - Результат на синтетиці: DSP 32/35, Basic Pitch 27/35 (без хибних спрацювань, але пропускає тихі). BP у браузері (WebGL) 0.6–0.9 с на 2-секундне вікно, затримка ~2.5–3 с. Деталі: `docs/AI-BASIC-PITCH.md`.
- **GuitarSet** (6. 11.): відкритий набір завантажено в `tests/recordings/guitarset/` (Zenodo 3371780, v1.1.0, CC BY 4.0, мікрофон). `npm run make:guitarset` ріже його на 681 акорд у `guitarset-segments/` (`scripts/make-guitarset-set.ts`, `scripts/guitarsetLabels.ts`), `npm run eval:guitarset` оцінює. DSP: 455/681 (66,8 %; 109× мовчить, 117× не той акорд). Basic Pitch: 383/681 (56,2 %; 253× мовчить, лише 45× не той акорд; 5,3 с на вікно в Node).
- **Власні записи** (51 файл у `tests/recordings/real/`, 6. 11., бракує `none-string`): DSP 42/51 (82,4 %; 7× мовчить, 2 хибні спрацювання на розмові), Basic Pitch 38/51 (74,5 %; усі 13 помилок — мовчання, жодного хибного акорду). Звіт: `docs/results/eval-real-2026-11-06.md`. Висновок: ШІ обережніший. Пристрій запису користувач ще не назвав.
- **Поріг ШІ налаштовано** (7. 11.): `npm run tune:basic-pitch` (`scripts/tune-basic-pitch.ts`) один раз проганяє мережу, кешує її вихід у `tests/recordings/.cache/basic-pitch/` і пробує пороги офлайн. Поріг обрано на GuitarSet, на власних записах лише перевірено. `DEFAULT_ACTIVATION_FLOOR` 0.25 → **0.075**: GuitarSet 383 → **505/681 (74,2 %)**, 32× не той акорд; власні 38 → **46/51 (90,2 %)**, 0 хибних спрацювань. Тепер ШІ точніший за DSP на обох наборах (DSP 455/681 і 42/51), але досі повільний. Звіт: `docs/results/tune-basic-pitch-2026-11-07.md`. Повний `npm run eval*` з новим порогом не перезапускали (очікувано ті самі цифри: на старому порозі 0.25 підбір точно відтворив звіти eval).
- **Швидкість ШІ + перемикач** (7. 11.): власний запуск мережі в `prepareRunner` (один прохід замість двох, лише вихід frames, `tf.tidy`; бібліотечний `evaluateModel` більше не використовується). Браузер WebGL 368 → ~110 мс на вікно, Node 5 850 → 1 713 мс, витоку тензорів немає. Відповіді на 51 власному записі ті самі (51/51). GuitarSet з новим запуском: 499/681 (73,3 %, було 505), власні 46/51; поріг 0.075 лишається. Виміри: `npm run bench:basic-pitch`, у браузері `benchBasicPitch()` (`src/audio/engines/basicPitchBench.ts`). Кеш нового запуску: `tests/recordings/.cache/basic-pitch-v2/` (старий `basic-pitch/` = бібліотека; звіт бібліотеки — `docs/results/tune-basic-pitch-2026-11-07-library.md`). На `/#/chords` перемикач «Алгоритм / ШІ»: `SoundHistory` (кільцевий буфер 3 с через AudioWorklet, `AudioInput.readHistory`), `useAiEngine` (завантаження + розігрів ~10 с, поки працює алгоритм), `useChordDetection` (ШІ кожні 0,5 с на останніх 2 с, стабілізатор (1, 2), поріг тиші через `LevelGate.clears`). Наживо на тестовому акорді: зміна акорду показується через 1,4–2,1 с, аналіз ~130 мс. Бічна картка «Як це працює» досі описує лише алгоритм.
- **Нестандартні акорди** (7. 11.): 108 шаблонів (major, minor, 7, maj7, m7, dim, m7♭5, aug, 5) у `chordTemplates.ts`; у 7/maj7/m7 квінта необов'язкова; `sameNotes` (Caug = Eaug). Правило рішення `classifyChroma(chroma, dbfs, ChordRules)`: нестандартний акорд перемагає лише з запасом над найкращим мажором/мінором (`extendedMargin`, `powerMargin`, `fallback`). Підібрано окремо для рушіїв на `guitarset-segments-ext` (762 акорди з анотації «played», `npm run make:guitarset-ext`) скриптом `npm run tune:chord-rules`: DSP 0.08 / 0.15 / always → 433/762 (басові 399); ШІ 0.02 / 0.06 / ifHeard → 598/762 (басові 433). За типами ШІ: maj7 69 %, m7 54 %, 7 51 %, 5 82 %, m7♭5 93 %; DSP: maj7 22 %, m7 16 %, 7 31 %. На власних записах (лише тризвуки) розширений словник трохи гірший (DSP 40 vs 42, ШІ 45 vs 46), тому на `/#/chords` є перемикач «Мажор/мінор | Усі акорди». Звіт: `docs/results/tune-chord-rules-2026-11-07.md`.
- **Мерехтіння акорду наживо виправлено** (7. 11.): причина — поріг тиші +12 дБ: акорд, що згасає, через ~1,5 с падав нижче порогу. Тепер `LevelGate` з гістерезисом (+12 вмикає, +6 вимикає) і `LiveChordTracker` (`src/audio/liveChordTracker.ts`: поріг, стабілізатори, утримання останнього акорду 4 с блідим). `npm run replay:live` проганяє логіку сторінки на записах: на власних записах акорд видно 56 % → 98 % часу, зникнень 19,8 → 0 за хв, правильний акорд на екрані 53 % → 95 %. Звіт: `docs/results/replay-live-2026-11-07.md`.
